# V1 风险射击与运行时回退对 V2 的对比分析

## 1. 结论

V1 最值得迁移的不是旧代码，而是两条已经被大量实战修正过的语义链：

1. 所有动作来源最终汇入同一个安全闸门。直接获胜捷径、Minimax、导航、
   隐身射击和技能动作都不能绕过已发射子弹、炸弹、同星对枪和控制效果检查。
2. 降级只缩减价值搜索，不删除硬安全。V1 即使进入最后一级回退，仍保留一次
   联合动作推演、根部死亡陷阱检查和最终动作安全替换。

V2 的 TypedArray、预分配 Arena、apply/undo、整数策略和分层缓存更适合作为最终
高性能实现；但冻结 Candidate 的实际结果说明，当前优势尚未兑现：本地发现赛道
V2 每局 P95 比 V1 高约 58%，官方 cold-smoke 在 3012ms 超时，且原生技能对局
胜率只有 32.27%。因此不应回退到 V1 架构，也不能直接复制 V1 的对象式状态；
正确方向是把 V1 的成熟安全语义移植到 V2 的零热分配数据通路，并重做 V2 的
搜索调度与平台降级校准。

本分析绑定以下不可变输入：

- V1：冻结 SHA-256 `8da68843a292c6a6230a32baf60392916f9fb85aaa5d9a94feac7085ddc9e82e`
- V2：冻结 Candidate `imp8-v2-a5ce6f8ef59abb61`
- 对战报告：`artifacts/diagnostics/v1-v2/imp8-v2-a5ce6f8ef59abb61/` 下的
  `v1_v2_exact_paired_failure_diagnostic_v1/failure-diagnostic-report.json`

## 2. V1 风险射击的真实控制链

V1 的射击不是一个分数函数，而是五层串联：

| 层 | 作用 | 关键语义 |
|---|---|---|
| 确定性威胁优先 | 已飞行子弹和临近炸弹先处理 | 已发生威胁优先于攻击机会 |
| 强制/优势攻击 | `winningAttackAction` 比较双方命中到达帧 | 我方严格更快才进攻；同时命中仅在星领先时接受 |
| 候选生成 | `fireUtility` 生成直射、预测拦截、清土堆射击 | 无意义的重复撞墙射击直接禁止 |
| 风险敏感搜索 | 最坏敌方动作与学习策略期望混合 | 最坏分支始终存在，学习模型只占 15%–35% |
| 最终动作闸门 | `saferRuntimeAction` 重算当前物理风险 | 任何上游动作都必须再次验证，必要时换成 GO/转向 |

V1 的风险值虽未归一化为 0–100，但已经形成稳定风险等级：

- `100000`：动作后立刻命中、穿越子弹位置、确定爆炸或确定单方死亡；
- `50000`：现有弹道没有足够逃生动作，或近距离枪口无法躲闪；
- `35000`：逃生余量为零，也是最终动作闸门的实质替换阈值；
- `10000`：只有一个动作余量；
- 更低值：远期、可逆或有多个逃生出口的可能风险。

这正好验证了设计中的边界：已飞行子弹、已落地炸弹及确定死亡属于 Hard；敌方
“可能开火”属于 Risk。V1 对可能开火不会一律判死，而是按枪口方向、距离、
子弹到达帧、我方朝向、速度、横向出口和星数决定风险等级。

### 2.1 V1 对风险射击的限制

`unfavorableImmediateRuntimeFire` 会把以下 FIRE 升为不可接受风险：我方星数不多于
对手、对手当前可开火、且对手命中帧不晚于我方。反之，只有星数领先且两格内的
确定直射，`favorableImmediateRuntimeFire` 才允许射击覆盖普通的 `35000` 风险阈值。

这套规则安全但不等于最终设计：它把风险偏好写死在多个阈值和星数分支中，不能
用统一的 0–100 风险参数连续调节。V2 应保留“到达帧竞争”和“最终安全闸门”，
但将非确定风险交给统一的 ε-contamination backup 与动态风险档位。

### 2.2 隐身和不可见风险

V1 会保留短期敌方姿态集合、草丛入口、cloak 的可能弹道以及 Overload 双弹轨迹；
最终闸门会对每个可能枪口和可能弹道求最大风险。它的优点是不可见不等于无风险，
缺点是大量候选使用普通数组和临时对象，且某些集合靠固定上限与 TTL 控制成本。

V2 当前不可见时主要依赖 `PossibleProjectileTracker`；若敌方不可见且没有已推断弹道，
`possibleShotRisk` 不再计算隐藏枪口。`HiddenRiskField` 虽已存在，但尚未接入生产根
决策。因此 V2 的 InformationState 射击/占位风险仍弱于 V1。

## 3. V1 性能回退的真实机制

V1 不是单纯按本地耗时回退，也不是单纯按回合数回退，而是双触发器，任一先到即
生效：

| 模式变化 | 累计脚本时间 | 确定性比赛进度 | 搜索行为 |
|---|---:|---:|---|
| 关闭 Monte Carlo | 1000ms | 64 | 永久停止 8×4 rollout 扩展 |
| Minimax 降级 | 2250ms | 100 | 最多 2 轮 |
| Minimax 紧急 | 2700ms | 112 | 最多 1 轮 |

比赛进度定义为 `max(game.frames, onIdle 调用数 - 1)`，所以平台没有 `Date.now()`、
本地计时不可信或同一帧多次回调时仍会确定降级。帧号回退时才重置整局计数。

正常情况下，V1 按距离、边缘、弹道、炸弹和控制效果选择 2 或 3 轮；根动作平均
分配 `128 / 动作数` 的节点额度。Monte Carlo 本身还有大量固定剪枝：活动子弹、
炸弹、自身控制效果、近战、确定枪口危险、确定射击和单一安全动作均不运行。

最重要的是，112 之后的“1 轮”仍模拟我方动作 × 敌方动作 × chance，再做叶评估；
Overload、近距离转向后开火、同星不利换血和最终 `saferRuntimeAction` 都不被删除。
这就是 V1 在 128 帧局中能把计算压低而不完全失去安全性的原因。

## 4. V2 当前实现对比

| 维度 | V1 | V2 冻结 Candidate | 判断 |
|---|---|---|---|
| 状态表示 | 普通对象、数组、clone | TypedArray、Arena、apply/undo | V2 架构更优 |
| Hard | 多个根陷阱 + 最终闸门 | `HardGate` + reverse viability | V2 更统一，但最终入口仍需闭合 |
| 风险参数 | 隐式固定阈值 | 策略 `baseRisk` = 20–80 | V2 更符合设计 |
| 对手模型 | 动作计数，最坏值与期望混合 | 多事件/多场景整数 EMA | V2 表达力更强 |
| 隐藏风险 | 姿态、草、cloak、可能弹道集合 | 生产路径主要只有可能弹道 | V2 尚未闭合 |
| 深搜 | 一条搜索链，2/3→2→1 | 浅根矩阵/证明 + 独立深搜 | V2 存在重复工作和语义断层 |
| 降级触发 | 时间 OR 固定进度 | 仅校准 work units | V2 缺少确定性帧下限 |
| 紧急路径 | 仍保留一轮联合动作与安全闸门 | 搜索为 0，但仍先算导航、特征和全动作分数 | V2 紧急短路不够早 |

### 4.1 风险参数已经存在，但只覆盖了部分链路

V2 的风险惩罚是：

`possibleRisk × (100 - baseRisk) / RISK_DENOMINATOR`

`baseRisk` 随策略在 20、35、45、65、80 间变化，值越大越愿意承受“可能开火”风险。
这与原始设计一致。对手开火偏好只在置信度增长后小幅调整枪口风险，不会修改我方
风险参数，也符合“同一局只学习对手、我方参数不在线漂移”的约束。

缺口在于风险输入：可见的当前枪口和可能弹道已经接入；隐藏姿态、隐藏枪口、
草丛路线以及跨回合逃生义务还未完整接入。因此公式正确不代表风险链已经闭合。

### 4.2 当前同时运行两套搜索

信息完整且发生战术接触时，V2 先用 `TankRootAdapter` 构建一帧矩阵并运行
SearchEngine/ForcedWin；普通非终局结果会直接落到 ordinary leaf。之后又运行独立的
`ProductionDepthSearch`。前者不能提供深层普通局面价值，后者又不能复用前者已经做过
的根联合动作检查。这是当前最主要的结构性重复计算之一。

InformationState 下，第一套搜索因 `exact=false` 不运行；第二套搜索又要求敌方可见，
因此经常得到 `completedDepth=0`，最后只剩单帧 Hard、`possibleRisk` 和动作分数。
24 个失败窗口中有 12 个进入 InformationState，7 个出现零完成深度。

### 4.3 V2 的 fallback 档位削减不够明显

冻结 Candidate 的四档参数为：

- depth：`[3, 2, 2, 0]`
- node：`[128, 128, 128, 0]`
- proof：`[128, 128, 128, 0]`
- matrix iterations：`[48, 40, 24, 0]`

DEGRADED 到 FALLBACK 只继续减少矩阵迭代，深度、节点和证明预算完全不变；而进入
EMERGENCY 前又没有帧数保险。G10A 的 21,475 个 V2 决策中，10.15% 到达 reduced
mode，紧急动作数为 0。官方平台却先在 3012ms 超时，说明 work-unit 权重与阈值没有
覆盖真实平台成本。

此外，EMERGENCY 模式虽然跳过两套搜索，但 `selectAction` 仍先准备导航、计算策略
输入、遍历 Hard、计算每个动作的完整特征和分数，再调用 EmergencyEmitter。
它不是一条真正的常数级紧急路径。

## 5. 对战与性能证据

完整发现运行使用 244 个历史场景、2 次重复、4 个座位/技能变体，共 1,952 局。
原生 V1(stun) 对 V2(poison) 的 976 局中：

- V2：315 胜、661 负，胜率 32.27%；
- 488 个换边配对：V2 双胜 55、双负 228、各胜一局 205；
- V2 失败：515 局子弹/碰撞、20 局炸弹、126 局 128 帧终局；
- 原生动作占比：V1 FIRE 8.58%、GO 47.97%；V2 FIRE 6.17%、GO 67.74%；
- 51 个同星 128 帧失败中，V2 本地累计执行时间全部高于 V1。

全部 1,952 局的本地每局 P95：V1 为 561,326µs，V2 为 887,988µs；V2/V1 原生累计
计算约 1.53 倍。本地绝对值不能映射为平台 3 秒，但方向与官方 3012ms 超时一致。

V2 的低射击率不是“过于激进射击”的证据。更直接的问题是 GO 比例过高、隐藏状态
零深度、射击后/炸弹后的跨回合计划未接入，以及两套搜索重复工作。调整 FIRE 分数
不能代替这些结构修复。

## 6. 建议的实施顺序

### P0：先闭合语义，不调权重

1. 在 V2 建立唯一 `FinalActionGate`：所有直接捷径、搜索、计划延续和紧急动作都经过
   同一组已提交威胁检查；实现必须复用 Hard/Hazard 数据，不新增对象。
2. 把 V1 的 `attackArrivalFrames` 抽象为整数 `InitiativeRace` 特征：同时命中、星数、
   护盾和可逃生性分别进入 Hard、ForcedWin 或 Risk，禁止把“可能开火”升级成 Hard。
3. 将隐藏姿态、隐藏枪口、草丛与 cloak 可能弹道写入生产 `HiddenRiskField`，并让
   InformationState 执行有预算的 AND/OR/robust backup，不允许默认零深度。
4. 接通 `PersistentPlanArena`：射击、放弹和逃生动作必须持有到弹道/炸弹失效，且每帧
   用 Hard 重新验证 continuation。

### P0：重做平台回退

1. Runtime mode 取 `max(work-unit mode, deterministic frame floor)`；可用时的时钟只作
   第三重提前触发，不作为唯一真值。
2. 预注册真正不同的预算档位，例如 FALLBACK 必须同时减少 depth、node、proof 和
   matrix；具体值由函数、复合场景、全局模拟、终局四层 benchmark 决定，不能在旧
   Candidate 上原地修改。
3. EMERGENCY 在根状态导入后立即短路，只执行预计算动作顺序、Hard/Hazard 与发射；
   不运行路径场、策略切换、完整特征点积或任一搜索。
4. 128 帧前保留单独终局预算；同星时将预计剩余计算成本纳入动作选择和搜索启动条件。

### P1：消除重复工作

1. 每个根动作只计算一次 projected cell/direction、Hard、risk、direct hit、mobility，
   写入预分配 RootActionFrame，策略和紧急路径只读数组。
2. 合并浅根矩阵与深搜的物理 transition：根矩阵结果成为深搜第一层，而不是再次
   apply/undo。矩阵只在关键节点求解，普通节点使用快速上下界。
3. 将可共享的弹道、炸弹 blast、距离场、射线和逆向可生存结果按 generation 缓存，
   失效条件必须由事件驱动，而不是整帧清空。

### P2：再调风险和射击

在 Hard、InformationState、计划延续和 runtime 关闭后，才使用历史回放反事实与
V1/V2 换边对战调节 `baseRisk`、FIRE、预测拦截和盲射分数。否则权重会掩盖结构错误，
并在另一类地图上重新出现。

## 7. 可重复运行脚本

完整或续跑：

```sh
./tools/v1-v2-diagnostic.sh
```

小批量、多重复、显示更细进度：

```sh
./tools/v1-v2-diagnostic.sh \
  --limit 8 \
  --repetitions 4 \
  --max-traces 8 \
  --progress-every 8 \
  --output /tmp/v1-v2-repeat-4
```

输出包括 exact/trace 阶段、百分比、elapsed、rate、ETA、new、resumed、场景和变体。
相同输入与输出目录会从 JSONL journal 续跑；改变重复数或场景范围时使用新目录。
为了不改变 V1 的 `Date.now()` 回退和同星计时行为，脚本刻意单线程运行，每局都创建
新的隔离 VM/context，不能用并发结果替代该对比证据。
