# 持续优化策略：从假设到可验证收益

当前实验执行入口已具备预算、评估与停止门禁。下一阶段的主要工作是定位算法损失机制，而不是继续扩建流程或开启又一批无目标的百轮调参。

## 目标与当前证据

质量主指标使用不同地形地图上的配对得分，另设死亡风险、实际决策时间与内存约束。质量提升和纯性能提升分开确认。具体最小有意义收益及非劣界限在候选准入时冻结，不能在看到确认结果后修改；所需样本量依配对方差及独立地图数规划，100 轮或 1000 局不自动代表证据充分。

BP407 的 16 个状态仅用于机制诊断及回归：9 个反事实改善、5 个持平、2 个退化，总体区间仍含零。其中 5 个改善动作原本已被软控制允许、3 个被排除、1 个未进入搜索。512 名义预算消耗约 3 倍节点，没有确定收益。不能据此宣称算法已到上限，也不能把反事实最佳动作当成可部署策略。

## 第一项工作：对齐状态预测，分解动作排序

在既有 16 个冻结状态上建立有界诊断，先回答两个问题：

1. 相同物理状态、双方动作和可控随机事件下，搜索内部预测与已校准参考模拟器的下一状态是否一致？比较位置、朝向、存活、弹丸、炸弹、技能冷却、星数和事件发生顺序，输出第一处分歧。运行时字段单独处理，不用真实耗时平局规则污染质量目标。随机过程无法对齐的分支标注为无法判定，不能计为模型错误。
2. 对转移已对齐的动作，逐项记录估值、终局判定、搜索截断、对手响应权重以及最终执行门禁；定位为什么一个已允许的动作没有被选择。一次有利续跑不等于排序错误，应使用固定后缀验证并保留退化对照。

先检查已有改善且允许的状态 1、3、5、6、12，以及退化对照 9、15；完整 16 状态均保留用于诊断回归。优先级用于安排分析顺序，不能把有利状态选出来作为最终验证集。

交付是“状态 → 首处分歧/无分歧 → 可能机制 → 能证伪该机制的实验”，而非又一份输赢汇总。若存在参考模拟器与平台的不一致，先保留模型不确定性，不把本地参考当作平台真值。

本诊断应先冻结一个测量块、单步比较数量和墙钟上限；达到上限或足够回答问题即结束。不能把大诊断藏在返回 `games: 1` 的适配器中。对局任务逐局列明，非对局比较另列工作量与实际耗时。未形成机制证据，不准入质量候选。

## 策略优先级及分支

| 顺序 | 研究方向 | 启动依据 | 产出与退出条件 |
| --- | --- | --- | --- |
| P0 | 状态转移与事件时序 | 模型与排序尚未区分 | 可复现分歧则做最小修复；在检查范围内一致则进入排序分析，不反复扩测同一问题 |
| P1 | 已允许动作的排序、终局值和截断估值 | 5 个已允许动作存在改善信号 | 每个候选只改一个有证据的机制；机制检验失败即淘汰 |
| P2 | 软控制动作排除 | 3 个被排除动作存在改善信号 | 仅研究明确状态类别；Hard/finalGate 不放宽，并保留死亡率增加的反例 |
| P3 | 按状态分配计算预算 | 只有在某类状态已证明额外预算能改变并改善决策时启动 | 采用等实际时间对照；无收益则停止，不统一增加预算 |
| 独立性能线 | lazy-parity 目标环境验收 | 已有本地上传形态收益 | 验证真实平台、完整内存和绝对时限；不能将本地提速直接换成更大搜索预算 |

前两项是当前主线。暂不开展全局参数扫描、统一加深搜索、未经证据支持的缓存重构或整体算法重写。

## 持续循环

每个阶段的输出必须改变下一步选择：

1. **观察**：从失败状态、回归和热点中列出机制假设；至少包含一个会推翻假设的观察。
2. **准入**：为候选登记机制、作用状态、单一改动、主要指标、数据来源、最小实际收益、安全约束、成本与停止条件。登记为“可实现”不等于“可确认”。
3. **小试**：同时维护最多 2 个活动候选，先在机制状态上验证是否真实生效，再使用冻结探索集检查副作用。默认从一个小批次开始；最多 10 轮必须评估，不为凑整补实验。
4. **评估**：决定保留、淘汰、改进、退回或停止。实现未生效先处理实现问题；机制预测被证伪则淘汰；精度不足只允许事先有依据的数据补足方案。改进须解释新机制，不能只换相邻参数。
5. **确认**：名单、代码、阈值和样本一次冻结，使用未参与选择的新独立地图；执行全部预注册样本，不能边看结果边加种子。确认预算不足则不启动。
6. **验收与积累**：质量、资源、安全和目标环境均符合要求才建议采用；不确定或负结果也进入记录，并更新后续方向优先级。

生产基线只在完成验收后变更。每轮研究保留一条稳定基线，候选改动可独立撤回。停止某一方向后转向已有证据支持的下一方向；没有这种方向时暂停计算，转为补证据，不无限运行。

## 每批评估必须回答

- 改动实际进入了哪些决策？搜索、提案、最终执行各有多少？未生效的改动不能算“算法无收益”。
- 对预期失效机制是否产生预期影响？是否出现会推翻假设的反例？
- 主要指标的配对差与区间是多少？地图数、重复种子数和对手覆盖分别是多少？
- 改善是否以死亡率、最坏延迟、内存或某类场景退化为代价？
- 下一批预计回答什么尚未回答的问题？若只能重复已有结论，则停止。

按照 `experiment-execution-bp408.md` 提交绑定当前批次摘要的评估；代理可生成评估，无需逐批请用户确认，但必须有可复核证据。科学分析仍按冻结规则完成，执行器只强制流程和记录约束。

## 跨项目持续改进

项目编号变化不能清空历史负结果和累计成本。为每个机制族维护：证据、已测变体、结论、不确定性、耗时、局数和重开条件。相同机制仅因换参数、种子或项目名不得重新准入；须出现新的状态分歧、新的独立数据，或证明原实验无效的可复核证据。

每完成一个项目，检查策略组合与资源分配：优先解决会改变后续决策的不确定性；已证伪方向不再分配优化预算；候选枯竭时不把余额自动转为基线测量。每个项目的 100 轮上限不构成后续项目自动获得新预算的理由。

这是研究策略约束；现有执行器强制的是单项目门禁。跨项目机制去重、真实数据独立性和评估科学有效性仍需依据累计证据审核，不宣称已由程序自动证明。

## 如何衡量优化流程自身

分别记录三个分母，避免用“完成轮数”代替进展：

- **机制可判定率**：得到有证据支持或反驳结论的假设 / 已实际检验的假设；证据不足单列。
- **质量确认成功率**：通过独立确认的候选 / 完成确认的候选；中止和无效实验单列。
- **采用率**：完成全部验收并实际采用的候选 / 准入候选；本地合格与真实平台合格分开。

同时报告每个可判定假设及每个采用候选的实际时间、总局数、独立地图数、复用数据比例，以及重复检验已淘汰机制的次数。零采用时不虚构“单位采用成本”；应报告累计成本与尚未采用。接受率并非越高越好，严谨的小试淘汰可以减少后续无效确认。

当前目标是先产出一个可证伪的机制解释，再决定最小候选。第一步结束的标志是能回答“预测错、评价错、动作被排除，还是证据仍不足”，而不是完成指定轮数。
