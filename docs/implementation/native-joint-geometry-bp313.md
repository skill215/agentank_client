# BP313：联合移动支持缺口细分

## 结果

沿用BP311/BP312的16场景、双座位32局，仅做影子诊断。2,328个搜索根、深度分布、停止原因、双方动作流及胜负均不变。没有启用新搜索策略，没有修改production。

| 几何/规则缺口 | 1,058个支持不足根中出现 | 133个首层未完成根中出现 |
| --- | ---: | ---: |
| 双方普通移动至同一目标格 | 658 | 58 |
| 眩晕影响、目标准备不完整 | 452 | 73 |
| Hard窄证明不完整（敌弹撞土） | 64 | 2 |

支持不足根可重叠，不能将第一列相加。此批首层失败的三个分组恰好覆盖133根；没有观察到直接交换位置或其它联合移动子类。眩晕组只表示存在stun且prepared target不完整，不声称已确认其具体冲突规则。

## 证据和边界

重新扫描当前battle-records：1,526个raw文件，1,283份去重回放，83,570条record。31次普通跟进空位（seat0为17次，seat1为14次），与旧证据一致，没有新增确定同目标争抢或交换规则的证据。

旧扫描器只分析成功移动事件，且某些计数位于双移动筛选之后。因此零successfulSwap/successfulSameTarget不能证明对应动作必然阻挡、碰撞或死亡；不把这些零计数用作否定性规则证据。回放没有在该扫描路径上给出双方失败的移动意图。

固定本地模拟器的顺序占位模型只能作为一种假设。过去普通跟进案例已说明它与官方观察可能不同，不能直接移植其冲突规则作为Hard事实。

## 实施

开发侧SearchSupportAudit增加frame-start位置、prepared target和有效效果掩码，并复用已有classifyJointGeometry。按每根统计所有失败的几何类型；每根仍最多保存两个短见证。效果判断复用kernel.active，避免把NONE_FRAME当成生效技能。

产物：`artifacts/native-causal-audit/bp313-joint-geometry/`，仅manifest、overview、roots.ndjson.gz。所有生产动作继续由原控制器选择。计时包含诊断开销，不作为性能改善或平台超时结论。

新增正反测试覆盖同目标、交换、技能不完整、NONE_FRAME以及多事件/单根计数。原跟进和fail-closed测试保持通过。

## 下一步

不再提高预算试图绕过规则缺口。优先设计未确定转移的保守区间传播：未知cell不能被删除或视为死亡，也不能凭假设产生exact/Proof；只有界足以区分动作时才提交决策，否则保留现有fallback。先用小矩阵oracle验证声音性及支持覆盖，再做影子实验；没有优势证据前不接管production。

眩晕联合移动与普通同格争抢应分别记录证据，未来如取得完整官方意图/结果证据，再独立扩展FastKernel。官方simulate/publish/challenge均未调用。
