# BP366 — 受限证书早拒绝，保持动作等价

## 结果

复用 BP365 冻结的 16 场景、双座位、OFF/SHADOW/ACTIVE 共 96 局，不重新选场。

- OFF 22胜9负1平；优化 ACTIVE 23胜8负1平，与 BP365 ACTIVE 完全一致。
- 双方完整动作流、参数、事件计数、终局结果与上轮 ACTIVE 零差异。
- SHADOW 的 2,755 根逐帧比较完整检查与优化检查的有效动作，含五批重复测量，零漏覆盖、零动作漂移。
- 完整响应展开由 2,755 次降至 3 次，提前跳过 2,752 次（99.891%）。3 次展开中仅 1 次支持并需要覆盖；原本已选择 FIRE 的两次支持不再重复认证。
- UT 431/431；错误、超时、root restore failure 为 0。

## 优化方式

新增 `tools/agentank/diagnostics/restricted-terminal-prefilter.js`，仅改变诊断计算的调度，不改变成功证书规则：

1. 原动作已是 FIRE：不需要证书决定是否改成 FIRE。这里保证的是动作等价，不是证书统计数量等价。
2. FIRE 不在候选、Hard 不允许、入口域不满足：不克隆、不展开。
3. 检查必须覆盖的敌方 NONE 响应的必要条件：双方位置不移动，己方射线必须在规范弹速范围内无遮挡到达敌方，且行动后星差为正。考虑双方当前位置的星拾取和 pickup lock，不用根星差简单代替。
4. 观察边界失败：不展开。
5. 只有上述必要条件通过，才调用原完整证书检查，仍遍历全部敌方动作与 chance，仍经过最终门。

这些条件只能提前拒绝，不能单独产生获胜证书。几何检查依赖已通过的限定入口域，不可脱离该域作为通用战斗规则。

## 五批同输入标定

固定 Node v24.16.0；每个根先运行一次未计时的完整/优化检查对，再进行五批测量，按根和批次交替先后顺序。每批均包含相同 2,755 个输入。单位 µs。

|---|---:|---:|---:|---:|
| 1 | 151327.394 | 4537.835 | 105.007 | 4.689 |
| 2 | 131146.151 | 1768.253 | 97.511 | 1.493 |
| 3 | 126462.340 | 1654.706 | 94.105 | 1.323 |

| 5 | 126763.012 | 1477.513 | 90.307 | 1.203 |

证书检查累计耗时降低约 97.0%–98.8%。这是证书模块，不是整个 minimax 的提速比例，也不是官方平台预算证据。

本轮 SHADOW callback 包含完整 oracle 和基准循环，故其总对局 runtime 不用于性能结论；工具将 shadowRuntimeRatio 设为 null，避免误读。优化 ACTIVE 实际证书调用累计约 10.370 ms，包含执行环境/JIT影响，不与上一轮时间直接作严格等输入比较。
