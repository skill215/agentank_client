# BP391：第四批十轮转向惩罚条件实验预注册

继承高效调优协议的固定身份、单因素、收益/安全/工作量晋级门。使用 BP386 的 1243 场景 / 2486 换位对局、固定 V1 时钟、炸弹 phase 适配器、128 节点预算与生产源码；生产默认不变，不调用官方接口，不提交推送，不开子 agent。

前三批反复使用同一 64 地图开发集。本批在观察新候选结果之前刷新开发和验证：按 sha256(bp391-development-v1:id) 选 64 个实际地图，再按 sha256(bp391-validation-v1:id) 选 128 个地图。两集均排除 BP388 开发和 BP388/BP389/BP390 全部验证地图，彼此地图哈希不重叠。场景全集曾用于全量分析，因此只是新的开发隔离划分，不是首次看到的盲测。

每轮只对 BP386 改一项，不组合到 R15、R28、R29 上。普通转向线性成本 12+10×连续次数、反向附加成本 110，以及连续附加成本 [第2次60、第3次180、第4次及以上360] 是独立部分。

| 轮次 | 唯一变量 |
|---|---|
| R31 | 连续附加成本减半，保留线性和反向成本 |
| R32 | 连续附加成本封顶 60 |
| R33 | 仅第 2 次连续转向移除附加成本 |

| R39 | 仅搜索递归转移 top>1 移除连续附加成本 |
| R40 | 仅模拟状态自身星数落后时移除连续附加成本 |

搜索 transitionValue 中 top=1 使用真实执行历史；top>1 使用模拟路径历史。所有候选只改 scoreTransition 的对应转向子项，scoreAppliedTransition 不变。非转向评分、Hard、Risk、叶值、intent、动作域、终局和预算均不改动。

准备阶段在新开发 128 局验证 noop 与 BP386 等价，再验证新包装的 reference-half 与 BP389 R15 全量缓存中的对应局、reference-r29 与 BP390 R29 全量缓存中的对应局逐动作/终局/计数及搜索工作量一致。共 384 局预检，不算候选轮次或新策略收益。新开发集上两条旧候选的配对结果只作参考，不影响预注册十轮或门槛。

晋级：开发净局分至少 +2；验证和全量净局分 >0；单方死亡负局及换位双负均不增加；节点不超过同集基线 2 倍；error/timeout/restore 为 0。全量通过只取得诊断候选资格，不自动采用生产。

沿用逐局校验和检查点、每进程最多推进一阶段、完整产物不可覆盖。全量复用同变体已完成的开发/验证 384 局，实际执行与复用分母分开。所有轮次结果出炉后不改样本、变量或阈值。
