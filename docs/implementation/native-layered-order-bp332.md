# BP332：同根完整层调度POC

## 实现选择

复用已有`complete-layer-scheduler`和`prepareLayered`，没有另建搜索器，也未修改生产默认。扩展BP331隔离重算工具的`--layered`模式：先记录原搜索真实applyFrame次数，再以该次数作为完整层搜索的工作上限。根和递归评分保持当前混合定义，intent/Risk/候选域不变。

这是**相同物理转移上限**，不是相同墙钟时间，也不是相同policy节点数。完整层重新探索浅层会重复工作，快照和诊断开销未做生产性能资格。

## 结果

8个根×3种访问顺序（原顺序、倒序、移位）：全部能提交至少1层。每根三种顺序的已提交候选值、默认提案和WORST_INTENT提案完全相同，16个同根顺序对比均无差异。

对照BP331，混层调度有15/16次评分变化、6/16次默认提案变化。此次没有增加各根物理转移上限。

与原混层估值相比，默认提案仅CM22由RIGHT变GO、CM23由RIGHT变GO；其他6根不变。WORST_INTENT仅GPI22由STUN变RIGHT。`column-order.json`中的currentChanged=6是2根×3顺序**相对旧搜索**的变化，不是分层内部仍有6个顺序差异。

## 解释与限制

本轮证明在这8个已知根中，完整层提交能消除观测到的列顺序效应；不证明所有局面顺序无关，更不证明胜率提升。递归不完整、隐藏支持、未知残余仍独立存在；完成深度不等于ForcedWin证书。

重要成本问题从“先列深、后列浅”变为“较浅完整层 + 未完成深化的沉没成本”。不应该立即用启发式拒绝深化来掩盖成本；先衡量完整层在代表性局面上的覆盖和胜负。

## 下一步

先把同一个调度POC接入固定16场景诊断候选，保持当前默认混合评分，而不是延续已拒绝的全局WORST_INTENT。预算选取必须预先固定、使用明确工作单位，不能运行旧搜索后再运行新搜索作为真实候选，也不能根据战斗结果调参。

在ACTIVE前需要确定统一预算合同及零完整层fallback，并核对重复浅层开销。已有历史完整层实验/133个depth0案例应先复用，避免把已知的物理支持阻碍再次误判为调度失败。若仍需同输入成本基准，单独报告，不用本轮2局重建耗时代替。
