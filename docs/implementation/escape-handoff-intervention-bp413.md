# BP413：第 104 帧 GO 单步救援验证

2026-10-04。本批确认：在状态 3 的冻结环境中，第 104 帧仍可挽救。保持第 102 帧 FIRE，只把强制逃生接管时选中的 LEFT 改发为已通过 Hard 与最终门禁的 GO，即可让全部 32 条续局避开原先的炸弹死亡。

## 冻结实验与结果

沿用 BP411/BP412 的 32 个种子，逐对比较原 LEFT 与一次 GO 干预，共 64 局。第 104 帧之前完整动作前缀、物理状态、风险及选择器快照完全一致。32 局 LEFT 的完整行为签名复现 BP412。

干预只替换第 104 帧实际发出的动作及相应已选行记录，正常执行发出动作后的状态更新；保留先前已完成的仲裁内部更新，不额外调用意图提交。第 102 帧仍按旧协议固定 FIRE，之后全部由生产策略继续，不放宽门禁。

| 指标 | 原 LEFT | 第 104 帧 GO |
|---|---:|---:|
| 已知炸弹爆炸时存活 | 0/32 | 32/32 |
| 完整续局胜/平/负 | 0/0/32 | 10/18/4 |
| 平均得分（胜1、平0.5、负0） | 0 | 0.59375 |
| 最终死亡 | 32/32 | 4/32 |
| 因该炸弹死亡 | 32/32 | 0/32 |

全部游戏均实际运行到第 108 帧并观测到已知炸弹爆炸，没有用提前结束的胜局替代爆炸时存活。

主指标的配对存活差为 +1，前后 16 对均为 +1，精确单侧配对符号检验 p=2^-32≈2.33×10^-10。达到预设的存活差至少 +0.50、p≤0.05、两半同向要求。完整得分差 +0.59375，两半均为 +0.59375，也达到预设 +0.10 的次级要求。完整续局死亡率差为 -0.875。

这些是已经筛选的同一个历史状态、同一批种子的条件机制证据。低 p 值不消除历史选择偏差，不代表独立地图泛化或一个可部署策略的效果。

## 仲裁原因已复算

独立 Python 复算 64 份干预前快照，全部还原原算法选择 LEFT。两动作均为允许、可接受、未被支配；NONE 尾部行在 `risk.count` 之外，未把其旧缓存纳入比较。

| 仲裁字段 | GO | LEFT |
|---|---:|---:|
| 逃生证明等级 | 2 | 2 |
| 截止时暴露标记 | 1 | 1 |
| 逃生后继 slack | 3 | 3 |
| 可行下一动作数 | 3 | 3 |
| 即时死亡风险 | 0 | 0 |
| 窗口死亡风险 | 1875 | 1875 |
| 首个预计危险帧 | 3 | 3 |
| 软逃生余量 | -1 | -1 |
| 最终决胜字段 `robustLower` | -6012 | -5738 |
| 战术分 | 172 | 872 |

`StrategicArbiter.selectEscape` 先比较逃生证明、暴露、slack、分支数，随后比较风险字段。本例前面的字段全部相等，最终以较高的 `robustLower` 选 LEFT，因而在仍可行动时转回了原朝向。

`DeadlineKernel.evaluateSuccessor` 对可行或未知后继设置 `arrival=1`，随后计算 `slack=deadlineTick-arrival`。这个证据余量没有表达从不同后继姿态实际走出炸弹范围所需的完整时间；它不能单独区分本例的及时移动与继续转向。这是指标语义和仲裁需求之间的具体缺口，不能据此否定整个安全证明系统。

本批不证明第 105 帧安全门禁拒绝错误。它证明的是：第 104 帧两项合法选择具有显著不同的条件续局结果，当前逃生排序没有区分出来。修复应优先发生在仍有合法行动的阶段。

## 验收与决定

- 64 局完整回放，32 对干预前状态和仲裁快照一致，32 局控制组签名完全复现。
- 320 个真实事件步骤、377 个随机事件值独立核验。
- 64 次仲裁选择独立复算，首个决定 GO/LEFT 排序的字段全部为 `robustLower`。
- 核心回归 592/592 通过。生产源哈希未变，无隐藏重跑，无优化轮次或候选采纳。

**决定：保留生产版本，转入有明确条件的局部候选设计。** 下一批建议只构造一个实验候选：在强制逃生、已知炸弹且现有证明与前置风险指标相同的情况下，加入“实际逃出危险区所需时间/逃生进展”作为启发式分值之前的比较依据。所有 Hard、最终门禁及严格更安全动作的优先级保持原约束。

候选必须以真实状态和动作计算，不按状态编号、帧号或动作 GO 硬编码；需先验证指标时序及适用边界，再在冻结的独立场景与安全回归中比较。GO 仍有 4 局后续弹丸/碰撞死亡，不能把本次改进理解为全局安全保证。
