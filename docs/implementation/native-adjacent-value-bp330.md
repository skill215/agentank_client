# BP330：相邻根搜索支持审计

## 结论

发现明确的**同一行内敌方响应搜索支持不对称**：row-shared预算被前列消耗，后列常直接成为预算叶；根最坏值排序仍把这些不同深度的估计直接比较。应先验证预算调度，而非继续调intent、窗口或战略分数。

另有已知目标差异：实验根使用worst+intent优先，递归worstReply仍返回blended(min, weighted mean)，policyValue取该混合值最大。实验不是纯递归minimax，也不能从根选择声称后续策略已一致优化。目标差异是合同事实，尚未独立量化其胜负贡献。

## 证据

6根共68个响应格，44格只有1个节点且触发预算叶；23个可选动作行中，20行的最坏值包含这种单节点预算格。

只重建CM、GPI两局既有全程候选轨迹，记录CM21/22/23、GPI15/16/22共6个根的每格value、节点前后计数、预算叶、深度叶、Fast不完整和policy叶。双方完整动作流、参数、结果及计数与BP326一致，观测未改变行动。

CM22：每行预算32。

| 我方动作 | 敌方响应 | 节点计数前→后 | 值 |
| --- | --- | --- | ---: |
| GO | GO | 0→51 | 1404 |
| GO | LEFT | 51→52 | 687 |
| GO | RIGHT | 52→53 | 687 |
| RIGHT | GO | 0→40 | 5517 |
| RIGHT | LEFT | 40→41 | 475 |
| RIGHT | RIGHT | 41→42 | 475 |

后两格均只有1个预算叶、0个深度叶。最坏排序比较GO687与RIGHT475；期望则1257与4488。首列已较深入探索，后列是预算截断估计，不构成同深度保证。实际敌方该帧为GO，但这只是事后校验，不能让搜索预知敌方动作。

CM23的首个保留敌方响应变为LEFT：RIGHT对LEFT节点0→50值7935，对RIGHT节点50→51值810；STUN对LEFT节点0→55值899，对RIGHT节点55→56值910。最坏值比较把浅估的RIGHT810与较深入的STUN899放到一起。

GPI16：FIRE对GO节点0→31值11168；对LEFT节点31→32值-327并触发预算叶；对RIGHT节点32→33仍-327。实际敌方命令为RIGHT，正好落在浅预算格。不能据此认定真实行动必败，只能确认该响应没有得到同等续行探索。

节点数可以超过perRootBudget：预算控制叶截断，不是硬中断全部尚未完成的兄弟分支。不能将数值超过预算直接称为平台超时bug。

## 目前不能声称的结论

- 不能证明所有退化由预算调度引起；正例也存在同样结构。
- 不能用这些值构造严格Hard/ForcedWin或真正数学上下界。
- 尚未记录父节点选中的完整续行策略和下一帧完全相同物理状态，不能声称已证明动态不一致。
- intent上下文epoch变化可由局面变化引起，未发现可确认的intent提交错误。

## 下一步预注册方向

先做**同根敌方列顺序置换审计**：保持候选、概率、预算总量、估值和动作选择目标不变，在隔离诊断中交换敌方响应访问顺序，检测矩阵值和最终选择对顺序的敏感程度，实际行动仍执行原策略。每次必须恢复root及全部搜索缓存/计数，或使用独立实例；不能把污染后的重算称为同根对比。

若顺序效应显著，优先设计预算内分层矩阵完成策略：所有格先有共同浅层，再按完整层提交深层结果，中断不把不同层结果混成一个已完成矩阵。需单独验证性能、动作和完整对战，不直接把cell-equal当已证实更优，也不增加全局预算。
