2026-10-04。结论：诊断重点应从泛化的权重调优转向第 104 帧的强制逃生接管。现有记录不能证明最终安全门禁判错，也不支持直接放宽门禁。

本批冻结 BP411 状态 3 的全部 32 对种子，重放 FIRE/RIGHT 共 64 局；只记录第 102—108 帧，直到根节点已知炸弹爆炸。64 个完整行为签名均与 BP411 一致，无新增策略、无优化轮次、无重跑。核心回归 590/590 通过。

## 为什么不能归结为“评分没看到炸弹”

1. 当前状态的炸弹压力在第 104 帧已升至 3500，第 105 帧升至 35000。风险已有可量化表现。
2. 第 104 帧进入 `COMMITTED_ESCAPE=1`，`action-owner.selectOverride` 按现有设计退出，战术搜索不再负责动作选择。记录中的 `NON_CONTACT_MODE` 也包括强制逃生，不能误读成战略导航。
3. 第 105—108 帧全部动作被最终门禁拒绝，`lastSelectedRow=-1`，实际输出 NONE。不存在一个仍有效的搜索候选被执行。尾部 NONE 行可能保留旧评分/风险缓存，不能用于解释选择。
4. 根节点虽然设置深度 3，但实际 LEFT 响应的两个眩晕分支都因预算在第 1 层截断。该响应单独比较时 RIGHT=-1602、FIRE=-1797，本来偏向 RIGHT；FIRE 被选仍受其他假设响应的混合分影响。此事实不足以重启历史上已被拒绝的全局预算/顺序候选。

因此目前有一条被 32 次重复确认的执行链：根 FIRE → 第 103 帧转右 → 第 104 帧逃生接管选择转左 → 第 105 帧全拒绝 → 原地等待 → 炸弹死亡。尚未证明第 104 帧 GO 的完整后续效果，亦未证明第 105 帧全拒绝是误判。

## 转移与数据完整性

- 448 个连续影子步骤，使用实际发出指令和同一随机事件，逐帧比较本地参考；不重新规划。
- 384 步全部规范化物理字段一致。其余 64 步均位于炸弹爆炸帧，只有己方炸弹冷却差一帧（模型剩余 9，参考剩余 10）。448 步双方毁伤状态全部一致。因此这次炸弹死亡不是影子模型无法模拟爆炸。
- 896 次静态逃生查询由独立 Python BFS 复算通过。该查询有忽略敌人和固定敌人两种几何条件，均不声称战术安全。
- 观测层仍有弹丸字段差异：FIRE 第 107 帧 15 例，RIGHT 第 106/107 帧各 15 例。这些差异保留在证据中；关键 FIRE 第 104/105 帧未发现规范化输入差异。
- 初次离线审计假设每帧都有 `selectedAction` 字段，因全拒绝时该字段未序列化而失败。修正为核对实际指令与完整动作流，并确认缺字段对应 NONE；128 个相关帧全部通过。未修改或重跑测量结果。

## 下一批的唯一干预

冻结第 104 帧的局部反事实：保留第 102 帧 FIRE 及此前前缀，只把第 104 帧已获 Hard 和最终门禁允许的 GO 与现有 LEFT 比较；之后仍完全执行生产策略，沿用 32 对种子。主观察为已知炸弹爆炸时能否存活，同时报告完整续局收益和死亡变化。

若 GO 不能稳定解除该失败链，停止将接管选择作为修复方向；若 GO 能解除，再追踪强制逃生仲裁为什么未选它，设计有明确适用条件的局部候选。不得跳过门禁、全局强制 GO 或以这个历史状态直接宣称泛化提升。

本批决定：保留生产策略，结束事件诊断，下一批验证第 104 帧选择的可挽回性。
