# BP294：原胜局退化的完整矩阵与复用机会

## 范围

仅对BP292两个原胜局退化根重新执行完整depth1–3，正反序共4次。记录每层根响应矩阵和物理转换键重复率；未调整生产策略、评分或预算，未启用缓存。
动作、续局结果和工作量与BP292一致，漂移0；正反序提交行值差异0。

## 退化一：7uqJ，seat0 frame15

基线GO获胜，完整depth2/3改为左转，续局为平。

| 深度 | GO rootScore | 左转rootScore | 左转ownerValue（+150 intent） |
| --- | ---: | ---: | ---: |
| 1 | -220 | -425 | -275 |
| 2 | -260 | -249 | -99 |
| 3 | -204 | -150 | 0 |

第二层开始，左转即使不计intent bonus也略高于GO；不是单纯删掉+150就能保证恢复。
第三层左转对敌右转的cell达到441，而其余敌方响应为-231/-212；递归备份和对手权重共同形成最终值。不能仅据实际某一条V1续局宣称minimax算术错误。

## 退化二：7E73，seat0 frame30

基线右转获胜，完整第三层改GO，续局为负。第二层仍选右转。

| 深度 | GO rootScore | 右转rootScore | 右转ownerValue（+150 intent） |
| --- | ---: | ---: | ---: |
| 2 | -863 | -351 | -201 |
| 3 | -669 | -974 | -824 |

右转对敌GO的cell从3787降到758；对敌左右转的cell从-1385/-1366降到-1407/-1393。GO对敌GO从-856升到115。两个动作在更深近似备份中的排序因此交换，最终选择并非预算半层污染，也不依赖根列顺序。

已用这些具体矩阵构建整数备份UT，重建排序一致。但此UT只证明算术与记录吻合，不证明启发值对真实长期胜率准确。

## 重复计算机会

开发侧按物理hashLo/hashHi加联合动作/参数/chance记录转换键：

| 根 | 第三层转换调用 | 同层重复键调用 | 同层重复比例 | 与此前层重复调用 |
| --- | ---: | ---: | ---: | ---: |
| 7uqJ | 961 | 318 | 33.09% | 99 |
| 7E73 | 944 | 312 | 33.05% | 99 |

这是潜在复用空间，不是已验证的缓存命中率或速度收益。跨层与同层重复可能重叠，不能简单相加。64位状态hash还不是无碰撞证明，键未覆盖所有kernel选项、历史上下文和规则版本。

生产leaf明确将pathScore加入状态评估，并可能施加路径重复/历史调整。新增UT确认同一物理hash、不同pathScore产生不同分值，因此禁止只按物理状态缓存最终搜索分。

## 下一步

优先验证语义中性的物理转换/纯状态特征复用，而非最终minimax分缓存：

1. 完整键覆盖状态、动作参数、chance、规则配置；需要验证hash碰撞或完整身份。
2. 命中仍须正确生成可撤销delta/events，保持实体generation与中断恢复；不能仅复制终局分。
3. 缓存关闭/开启的完整矩阵、动作和状态恢复必须一致；再比较真实转换减少量、内存和耗时。
4. 路径效用、历史/intent及对手上下文不在纯物理缓存中；涉及它们的值必须另行重算。

估值维度另行推进：应对改变排序的递归分支继续追踪路径收益/叶特征与实际对手响应，不凭两个样本调固定动作分。
