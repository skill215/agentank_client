## 证书边界

50局失败共4022帧，仅2帧进入完整证书展开、0次覆盖：

- `mat_GuRNTmoMyq08h0NRb` seat1，64帧死亡，星数2:0。
- `mat_EYdWYmKm6uZB3sJg8` seat0，39帧死亡，星数1:0。

两者都记录 `INCOMPLETE_OR_NONWIN` 和 `BALLISTIC_TERMINAL`。这些是证书拒绝标签，不证明原动作必错，也不证明FIRE可胜。其余帧的预筛选原因未逐项保存，空reasons不代表完整安全、完整搜索或无攻击机会。

逐局摘要中的通用searchRoots/searchNodes计数不能直接解释为实际minimax调用量；在核实埋点所有权前，不据此声称“失败局没有搜索”。

## 下一步：一次有边界的因果审计

1. 固定上述14个双负场景为审计集合，优先检查其中13局早期单方死亡；其他失败保留为后续验证，而不是逐个加补丁。
2. 使用BP370相同确定性时钟、冻结源码和历史星序列重建已有轨迹。先要求双方动作指纹、终局、星数完全复现；不一致则停止该样本归因。
3. 每局只保留死亡前最多4个根的紧凑诊断：实际最终动作、动作拥有者、Hard/Safety/Risk/EO候选状态、搜索完成度和预算、FIRE候选是否生成/被排除及原因。不保存整局replay。
4. 对合法替代动作做统一短窗反事实并覆盖敌方合法响应，区分物理模型漏项、可活动作被门禁删除、门内排序错误、攻击时机错误、预算不完整及没有已知可逃路径。固定对手续写只作诊断，不能当Hard或Proof证据。
5. 先按同一根因聚合数量和可恢复上限，再选择一个具有完整证据的结构修复；不同时修改Risk、战略和搜索，不把后验幸存当成严格保证。

本阶段不支持“提高深度必能解决”“减少转向必提高胜率”或“放宽证书一定增加胜局”等结论。BP370的4局恢复仍仅为开发证据，p=0.125；不接入默认production、不执行平台操作。
