# BP407 四项交付与下一阶段判断

本阶段完成本地验收、失败状态数据集、有界诊断和流程控制器。共新增 960 局：上传形态验收 192 局（包含 16 局预热），因果诊断 768 局。生产源码未改动，未部署。真实平台执行、完整堆内存上限和平台绝对时限仍待验收。

## 1. lazy-parity 验收

压缩产物为 180,946 字节，比基线增加 81 字节，低于仓库配置的 204,800 字节限制。构建可重复，源码和压缩产物行为一致；独立复核了 176 条完整对局记录，均与原生基线匹配。16 个配对案例的可观测类型化数组分配一致，每局累计唯一缓冲区字节为 400,574。这不是总堆峰值或平台内存认证。

采用全新进程 ABBA 顺序测量压缩产物，在受限 Math 的 Node VM 中几何平均耗时下降 **6.26%**。将两侧座位合并为地图采样单位，8 张地图的 bootstrap 95% 区间为 **4.43%–8.59%**。该区间不完整覆盖进程和顺序噪声；原样基线前后耗时比为 0.9786。此前原生进程的 29.6% 不能作为上传形态收益。本地目标形态验收通过，真实平台认证未完成。

产物：`artifacts/native-causal-audit/bp407-next-stage/runtime/`；可验收包：`runtime/build/candidate/minified.js`。

## 2. 失败状态集与路径追踪

冻结 16 个不同地形的历史状态：炸弹败局 4 个，弹丸或碰撞败局 4 个，星数落后 4 个，平局与胜局各 2 个。16/16 完整基线复现成功。保存可观测上下文、完整 FastState 数组、状态哈希、可用动作、Hard/finalGate 结果、软控制成员资格、搜索值和最终动作。

全程 1,547 次决策中，1,132 次进入搜索，647 次出现提案；这两个频率不代表提案改善率。选定状态中 14 个出现预算截断，2 个未进入搜索（敌方不可见、非接触模式各 1 个）。这些是结果分层选择的历史样本，不代表总体状态分布。

产物：`diagnosis/failure-state-dataset.json`、`diagnosis/cohort.json`、`case-diagnostics.csv`。

## 3. 预算与反事实诊断

每个状态只改变一次决策。名义预算 64/128/256/512，每档重复两次；128 对照完整复现基线。它们是行预算目标，并非总节点或实际时间硬上限。

| 名义预算 | 平均实际节点 | 改变动作的状态数 | 验证集配对得分差 | 地图级 95% 区间 |
| --- | ---: | ---: | ---: | --- |
| 64 | 114.56 | 1/16 | -0.03125 | [-0.09375, 0] |
| 128 | 163.44 | 0/16 | 0 | [0, 0] |
| 256 | 267.50 | 2/16 | -0.015625 | [-0.0390625, 0] |
| 512 | 489.69 | 4/16 | +0.046875 | [-0.03125, 0.1796875] |

得分为胜 1、平 0.5、负 0；上表不是总体胜率变化。预算动作在同一反事实验证后缀上比较，所有动作都有样本支持。512 约消耗 3 倍节点，没有确定收益；不采用统一加预算。诊断计时未按等 CPU 设计，因此不作等 CPU 效率结论。

单步反事实只执行通过 Hard 和 finalGate 的动作。前 4 个后缀种子用于选择，后 4 个用于验证。选择动作在 9/16 状态改善、5/16 持平、2/16 退化；平均验证得分差 +0.1796875，95% 区间 [-0.0078125, 0.3671875]，仍包含零。整体死亡差为 -0.21875，区间 [-0.453125, 0]，但状态 0、8、9、15 的死亡率上升，不能据此认定安全。

9 个改善状态中，5 个替代动作原本已被软控制允许，3 个被软控制排除，1 个未进入搜索。因此应优先定位允许集合内部的模型/排序问题，同时审查有明确例证的软控制排除；不能将问题全部归因于候选被拦截，也不能据此全局放宽安全或软控制。

这组结果说明局部动作存在可研究的差异，**尚未证明算法已达上限，也未证明某种新策略可部署**。转移模型错误与估值排序错误仍需独立校验的转移参考区分。每状态仅 4 个验证后缀，精度有限。

## 4. 统一流程与停止条件

实现 `tools/agentank/diagnostics/experiment-governor.js`，规范见 `docs/implementation/experiment-governance-bp407.md`。它输出派发决策，调用方必须在执行批次前消费该结果；本次没有改写历史 BP399–BP406 的执行器。

规则包括：100 轮为上限、每批最多 10 轮；无活动候选即停止；最多一次有明确成本的测量块；数据或样本精度不足停止；全部确认成本提前预留；确认名单冻结；安全或完整性失败停止；下一批成本不明或超出预算停止；不会自动发布或修改生产默认值。

实际决策快照：质量线 `STOP_NO_CANDIDATES`；性能线 `TARGET_RUNTIME_ACCEPTANCE_REQUIRED`。补充的假设性准入演示返回 `STOP_DATA_LIMIT`。这些均不派发实验。快照的实际墙钟尚未导入，不能当作新实验的预算授权；开始任何新项目须冻结完整成本与实际用量。

产物：`workflow/decisions.json`；完整性复核：`independent-audit.json`。Python 审计独立重算检查点哈希、行为签名、752 个前缀、128 个预算物理状态、选择/验证分离和统计区间。反事实物理状态在运行时逐个断言一致，但未全部持久化，因此补充审计不宣称独立重算了这部分状态。

## 下一步选择

保留 lazy-parity 作为待真实平台验收的性能候选。质量线结束当前参数与统一预算搜索；以现有状态集建立转移参考，区分模型与排序失真，然后只准入具备可证伪机制的候选。确认新质量收益需要新的独立地图，并按目标效应做精度规划。当前证据支持重构实验准入与停止流程，尚不支持整体重写算法。

验证：最终核心回归 **561/561 通过**；独立持久化数据审计通过，生产源码哈希保持不变。
