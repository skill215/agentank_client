# BP333：固定预算分层搜索ACTIVE

## 预先固定的合同

复用ThinLayerExecutor，固定每搜索根128次kernel.applyFrame、深度上限3，无准入预测、无参数扫描。完成层使用原生产混合评分、Risk和intent；没有完整层时prepare返回0，不消费旧矩阵，交回原incumbent和现有最终安全门，不重跑旧搜索。

128物理转移不同于旧生产的128 policy节点预算。该候选同时改变调度与有效工作量，不能称为仅改变调度的等成本实验。BP332已经单独验证同工作量的顺序稳定性；本轮验证的是可实际执行的固定预算组合。

## 下一步

先做“完整浅层 vs 混层”的同输入成本与价值来源对照，而不是提高深度：

1. 固定当前分层候选及预算，选旧数据中有代表性的同根输入，比较旧生产、完整depth1及分层128；分别报告完成层、工作量、P95和提案，不混入新评分。
2. 对7个胜转负与8个负转胜生成自动终局分类与首次分歧对账，分清浅层截断、无完整层fallback和一般值变化。不要根据个别退化直接加攻击分。
3. 只有成本合同与主要退化机制明确后，再安排独立场景验证；不把本轮65.625%作为已恢复全局水平的结论。
