# BP340：入口退化中的导航与意图所有权

## 结论

本轮定位到具体架构耦合：`ActionOwner.selectOverride`先调用`source()`，成功后才调用`intent.prepare()`。BP337几何入口返回null并不只是节省Minimax计算，还会阻止当前目标和意图动作更新。

因此BP339的“仅入口”实验是明确的代码路径处理效应，但不能解释为纯粹的“有无远距离Minimax”效果。它同时取消了搜索提案及后续意图更新。原导航并不是搜索栈全部导航能力的等价替代品。

不恢复几何入口限制，不直接把150意图加分改成新的强制规则。生产默认不修改。

## 样本与重建

从BP338 CURRENT及BP339 CURRENT_GEOMETRIC选出全部9个“CURRENT胜或平、受限入口版本在128帧按星数输掉”的案例，其中7个胜→负、2个平→负。

按压缩动作流定位首次分歧，分别重建两条已有轨迹，共18次。没有新策略对战或反事实续写。双方动作流、动作参数、整局分析结果与事件计数均与冻结记录完全一致，状态恢复、timeout、error为0。

首分歧3个在第2帧、4个在第3帧、2个在第4帧；9/9物理根的双方位置、我方朝向、星位置、双方星数一致，受限臂均命中source跳过条件。内部意图历史可以已经不同，不能把物理同根误写为整个控制器状态相同。

动作变化：GO→LEFT两例、LEFT→GO四例、RIGHT→LEFT三例；没有直接取消FIRE。

## 目标更新与选人证据

- 原版9/9根都有CHASE_STAR及非空target。
- 受限入口9/9根target均为NONE_CELL，proposed/committed/action均为0；上下文epoch已更新为1。这不是“所有观察更新都被跳过”，而是后面的意图prepare没有执行。
- 原版7/9最终选择不同于允许集合内的原始搜索值最大动作，150意图奖励改变了胜出动作。
- 另2/9原始搜索值就足以选择GO。其中一例intent推荐LEFT，搜索仍选择GO；所以也不能直接用intent映射代替整个搜索。

新增UT复现调用顺序：history→context→observeRoot→source；source空时没有intent.prepare，source非空才继续prepare。该UT是诊断现状，不是要求未来保留此耦合的设计规范。

## 对架构的含义

当前source把三种职责绑定在一起：获得搜索值、允许刷新意图、获得覆盖incumbent的资格。直接收紧搜索入口会同时改变三者，不能当作语义中性的性能优化。

下一步应先在诊断宿主拆清合同，而非调距离阈值：

1. 目标/意图更新具有独立生命周期，不取决于是否有搜索结果。
2. 搜索只决定是否提供搜索证据，不能隐式关闭目标更新。
3. “更新了目标”不自动取得最终动作所有权。Hard/Risk、搜索值与当前动作比较继续按原合同处理。
4. 用同根隔离对照先区分“仅保持意图更新”和“新增意图动作所有权”；不能一次把两者合并再归功于Minimax优化。

先要求原有搜索开启路径动作等价，再测试无搜索路径的目标更新合同。若未来要给无搜索目标规划增加动作所有权，应作为新的行为候选单独验收。仅分层128仍可独立做匹配输入性能标定，不再与几何入口捆绑。
