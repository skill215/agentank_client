# BP303：生产格架接线后的深度成本

## 范围与方法

生产tree仍为BP302的 `019352b765a19385e2c86b34096944af6f60e799d885abe92f50e5267e82b7eb`，没有修改生产。Node v24.16.0，18个固定真实根，每根每协议预热3次，五批每批3次。CURRENT和完整层上限1/2/3，共1080次计时搜索。每次恢复相同输入及冷根缓存，检查重复搜索矩阵/工作量一致、状态恢复；18场承载对局的双方动作流和胜负与原基线一致。

继续保留4096次apply上限及原scheduledDepth，不强制越过当前调度深度。完整层结果包括从浅到深的累积成本，开发侧调度开销也在计时内。所有时间都是本地搜索入口时间，不是完整controller或平台3秒时间。

## 结果

| 协议 | 达到请求层的根 | 所有尝试P50 | 所有尝试P95 | 仅完成请求层P95 |
| --- | ---: | ---: | ---: | ---: |
| 当前近似搜索 | 不适用 | 0.641ms | 2.568ms | 不适用 |
| 完整1层 | 18/18 | 0.214ms | 0.473ms | 0.473ms |
| 完整2层 | 16/18 | 1.084ms | 4.317ms | 4.585ms |
| 完整3层 | 9/18 | 6.040ms | 51.405ms | 16.916ms |

“完整”指该有限层的支持和枚举完整，不是终局Proof。各行完成子集不同，不能拿其P95直接做相同局面的深度倍数。

2层：2根因INCOMPLETE_SUPPORT停下。3层：9完成、4预算中断、4支持不足、1被原调度限制在2层。这几类不能混为“性能不足”。

| 协议 | 每18根apply工作量 | 未提交层工作量 |
| --- | ---: | ---: |
| 完整1层 | 236 | 0 |
| 完整2层 | 3,386 | 440（13.00%） |
| 完整3层 | 31,675 | 17,133（54.09%） |

CURRENT本次没有收集apply计数，不能与policyValue节点数混用。原始文件摘要中CURRENT的零是统计占位，不代表零工作；统计脚本已改为null，重算应使用导出的summarizeDepth。

## 判断和下一步

不应统一提深。完整2层可作为下一步开发调度器的候选已提交底座，但尚未授权为生产替代：旧实验已有“更深却选差动作”的估值退化。

下一步先做**影子层预算准入**：利用上一完整层的分支数/工作量、危险格架重建量预测下一层是否能在剩余预算内完成。评价应看完整层覆盖率、浪费比例和误拒绝可完成层数，而不是胜率或某几个根的最优阈值。不得因预测“不划算”而改变Hard，预算不足仍保留最后完整层。

这些18根已用于开发，不能用来调阈值后当盲测验收；准入规则需要独立局面或oracle测试。支持不足则继续如实返回UNKNOWN，不能通过加预算或伪装完整解决。
