没有改评分、战略purpose、Risk门、Hard或最终动作。逐根剥离新增poseDistance/poseProgress后，全部候选数据与BP342完全一致；双方完整动作流、参数、事件和整局结果也完全一致。

## 缓存与隔离

每控制器一次构造工作区。81根prepare共9次重建、72次缓存命中；样本19×15地图最大固定工作区4845字节。只是审计窗口内命中情况，不外推全局命中率。

只读接入发生在原incumbent选择之后；模块不接收可写Risk/Hard接口、不修改候选数组。生产tree与原输入不变。新数据没有包含完整replay。

## 接线实验边界

下一阶段可以建立独立的导航评分候选，但必须满足：

1. 基线仍为CURRENT原入口，不复活已拒绝的几何入口限制，不同时改变分层预算或搜索深度。
2. 使用同一份路线证据给导航评分和策略目标进度，避免评分认为推进而策略认为没有目标。不是新增一层强制动作所有者。
3. Hard/Risk及严格救援先行；正路线进度没有删除其他动作或恢复拒绝动作的权力。
4. FIRE、BOMB和技能的价值仍由其原模型负责，不用零位移进度否定攻击收益；不把boost/teleport/stun等效果假装为精确普通移动路线。
5. 缓存仍按目标与实际地形验证；生产整合前检查路径数组复用与总内存，不把实验工作区直接计作已合格生产内存。
6. 先做同根正反UT及评分消费者一致性验证，再冻结候选做ACTIVE。不能根据这8个失败根调权重，或只用它们的改善代替整局退化检查。
