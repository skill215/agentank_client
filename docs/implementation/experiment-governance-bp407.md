# BP407 统一实验流程

本规范用于后续算法优化。100 轮是预算上限，每次评估间隔最多 10 轮；候选耗尽、证据无法补足或预算用尽时结束。历史 BP399–BP406 的协议和证据保持原样。

可执行入口：`tools/agentank/diagnostics/experiment-governor.js`。输入冻结的项目状态 JSON，输出下一步决策；`dispatchOptimizationBatch: false` 时不得继续派发优化批次。

## 目标和证据

每个项目在运行前声明：目标环境、单一主要指标、最小有意义收益、安全约束、实际墙钟和内存限制、独立实验单位、数据来源以及验收环境。

质量优化使用配对地图级得分，先估计配对差异方差并规划样本量。精度不够应补数据或暂停。重复地图、两侧座位、随机种子和反事实续跑不作为彼此独立的地图。历史回归和合成压力测试不等于新的平台泛化证据。

性能优化先提供真实热点证据，随后做行为完全一致的小试。正确性影子、剖析和正式计时分别运行在全新进程。候选动态编译时加入原样重编译负对照；正式上线形态还需压缩产物和受限运行时验收。报告各运行环境的结果，不把原生 Node 提速直接当作平台提速。

安全规则（包括 Hard 和 finalGate）保持原有语义。诊断中可以比较被软策略排除、但仍通过 Hard 和 finalGate 的动作；只能在明确标注的单步反事实环境中执行，并记录选择前缀和实际干预。

## 阶段及退出条件

1. **定位**：先证明存在热点或可复现的损失机制。没有机制证据只允许诊断。
2. **准入与小试**：每个候选绑定一个机制、作用状态、可证伪结果和冻结分析方案。不得仅凭相邻参数变化重开已淘汰机制。
3. **探索**：单批最多 10 轮，提前给出轮数、局数和时间成本。活动候选为空时结束。明确的测量问题最多允许一个单独计账的测量块，不计优化轮数。
4. **确认**：先预留全部确认成本，冻结名单、输入、随机种子和阈值。确认中保留不利结果，不加样本追逐显著性。安全或完整性失败立即停止。
5. **验收**：本地行为、上传大小、目标形态性能、内存、实际平台环境分别记状态。通过本地 VM 不自动获得真实平台认证。
6. **收束**：记录拒绝、无效、证据不足、无活动、待确认、本地合格、目标合格。调度器不发布、不部署、不修改生产默认值。

每次派发前调用 governor，逐局检查实际预算和超时；预算统计包括标注、预检、预热、重复进程和复核。下一批成本不明或超出剩余预算，不得派发。确认已经完成时只分析固定结果。

## 必须保存的产物

- 冻结协议和源码哈希、基线身份、数据清单与分组。
- 逐局检查点、完整动作与参数、状态复现方法。
- 候选生效路径：可用动作 → 搜索 → 提案 → 最终执行。
- 预算变化的实际节点、时间和结果；等节点与等实际时间的结论分别报告。
- 探索与确认分离的统计报告、否定或不确定结论。
- 独立审计与目标运行时验收状态；真实平台证据缺失时明确保留该状态。

## 本次诊断的边界

BP407 选择 16 个不同地形的历史状态，覆盖 12 个败局和 4 个对照。各状态只改变一次决策，预算阶梯为 64/128/256/512 的名义行预算目标。允许动作在前四个后缀种子上选择，在后四个种子上验证。

这个有限实验用于定位“动作是否可改善、预算是否改变选择、软控制是否相关”。它不构成总体胜率实验，也不能单独区分模型错误和估值排序错误。后者需要独立校验的状态转移参考。
