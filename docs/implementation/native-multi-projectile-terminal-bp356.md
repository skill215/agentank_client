# BP356：多未知弹丸及处理顺序压力检查

## 结果

7个固定根，共49500个单帧响应分支：46290胜、3210平、0负、0未终局。6个领先根全部胜；同星根5790胜、3210平。

这是有界压力检查，不是全体多弹世界穷举，也不能视为49500局独立胜率样本。生产与风险门未修改。

## 冻结枚举范围

每个根先找出加入后我方完整snapshot不变的单敌弹位置/方向，按距两坦克最近距离、坐标、方向排序，固定取前24项，不按分支结果选择。

- 24项的全部276个无序二弹组合；
- 4/8/16弹各8个循环偏移组合；
- 合计300个集合，每组元素不重复；
- 敌方七种primitive指令及支持的stun分支；
- 每组比较NATURAL、REVERSE_ALL、OWN_FIRST三种弹丸处理顺序。

NATURAL为固定模拟器原顺序；其余两种是只在克隆世界上施加的诊断规则扰动，发生在弹丸推进开始前，包含新生成弹丸。它们不代表官方规则，也没有修改vendor。

每个组合先检查当前snapshot严格一致。真实场景原轨迹各重建一次，双方动作、参数、事件计数和结果完全保持。

## 边界反例与代码核对

已保留BP355的落后互毁、敌方盾挡子弹两个负例。新增phase反例：一颗不可见敌弹下一步将击毁我方；正常“先行动、后推进弹丸”下我方FIRE导致领先互毁胜，故意把弹丸推进放到行动之前，则我方单方死亡负。

这只是规则扰动测试，证明命题依赖相位；不声称平台真的先推进弹丸。初版用四颗同线弹做反例没有得到负局，因为后续弹越过已死亡坦克后还会击毁另一坦克；据此修正为同一单弹输入下只改变phase，未修改生产或放宽断言。

源码还显示两个不能混淆的顺序：模拟器按单颗弹丸推进完整步数，FastKernel按子步遍历所有弹丸；两者均在该阶段之后结算，但与地形、盾和碰撞结合时仍可能有差异。这里对模拟器数组顺序做了扰动，不等于已经对所有跨实现相位做穷举差分。

## 可用于下一步的合同，而非豁免开关

下一步可以实现仅Shadow的“命题依赖判断”，至少要求：

1. 候选行动能够执行，行动前无已知致命事件；不能用完整模拟器的隐含知识代替观察支持。
2. 对每个合法敌方响应，当前帧敌方被击毁有独立证据；护盾、无敌、位置变化、未知效果等必须覆盖，非终局不通过。
3. 星数在结算时严格有利；若可能拾星，必须使用分支后星数，不能只读根星差。
4. 未知敌弹仅增加已覆盖的弹丸事件，不能取消我方行动/已发射弹丸，不能改变已证明的敌方死亡；这一单调性需要规则级依据及适用范围，而非有限压力测试次数。
5. 只有8192这类被明确证明对命题无影响的缺失可做局部豁免；其他gap、预算不足、容量溢出仍不完整。全局informationComplete不变，Safety死亡质量不清零。

不再扩大随机/组合数量追求“更多全绿”来代替证明。应把上述依赖条件变成可检查合同，再针对规则缺口补窄oracle。当前仍strictProof=false，未接管动作。
