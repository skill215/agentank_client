# BP311：完整层搜索整局影子验证

## 结论

不能直接替换当前生产搜索。局部缓存和适配器加速是真的，但完整层方案做的工作更多，整局影子搜索入口耗时仍约为当前的4.11倍。当前主要阻碍是支持不完整与决策质量未知，而非预算中断数量。

## 分母与隔离

BP305冻结16场景、双方座位各一次，32局。只在当前生产真正调用prepare的根运行影子，共2,328根；没有强行给非接触或其它动作所有者的帧加搜索。影子使用相同根输入、4096 apply上限、深度上限3、冻结准入公式和4项格架。

影子运行后恢复Search、Kernel、Hard、Leaf、Path、FastState，危险场缓存单独隔离；随后运行原生产prepare并让其决定真实动作。32局双方动作流、分析胜负均与来源一致。结果21胜10负1平仅是保持原行为的证据，不是影子方案的胜率。

## 耗时与分歧

| 指标 | 当前生产prepare | 影子完整层 |
| --- | ---: | ---: |
| 32局搜索累计 | 2040.03ms | 8385.75ms |
| 搜索根P50 | 0.482ms | 1.978ms |
| 搜索根P95 | 3.289ms | 11.155ms |

影子每局搜索累计P95=630.83ms，最大690.85ms。这里只计搜索调用，不包含观察、整controller、影子快照恢复及其它对局成本；也不是平台时间。影子始终先跑，两路不是随机顺序的正式性能A/B，仍有JIT/缓存/GC顺序影响，不把4.11倍当作普适常数。

有完整提交的根中，root评分向量/动作域不同2,114次，原始最高分行不同649次。**不是649次最终动作改变**：统计只取rootScore、rootDomainMask，不经过Risk、intent和最终tie-break。没有运行ACTIVE轨迹，不能据此判断输赢。

按帧段0–31/32–63/64–95/96–127，搜索根数分别627/748/585/368，无完整提交根数17/60/39/17。问题不是只发生在局末fallback。

## 下一步优先级

先给1,058个支持不足根做低存储的原因归类，重点区分133个depth0：Fast transition规则不支持、Hard可活度不完整、无动作或其它支持缺口。仅记录首个原因与小型统计，不保存整局replay。

确认哪些是正确保守边界，哪些是真实实现缺陷；不放宽UNKNOWN、不改Hard证明，也不通过增加预算掩盖规则缺口。之后才针对有完整提交且出现决策分歧的根做战术结果分析或ACTIVE因果对照。当前不建议全面接入完整层作为最终动作所有者。
