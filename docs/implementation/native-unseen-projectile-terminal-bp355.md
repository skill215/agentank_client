# BP355：未知敌弹对单帧获胜命题的影响

## 结论

7个根均为informationGapMask=8192，但PossibleProjectileTracker活跃数为0、容量失败0、pool.complete=1。该池表示已生成的可能轨迹，不完整描述全局8192保留的所有未知世界；不能用池为空覆盖信息缺失。

独立模拟器加入单颗未观察敌弹的压力检查：4776个当前观察一致的世界、37272个联合响应分支，37212胜、60平、0负、0未终局。6个领先根全部胜；同星根为6060胜、60平。

这支持下一步研究**命题局部不变性**：无需证明没有未知敌弹，而是证明在某个已核验的终局动作上，它们不能把胜局变成负局。当前仍不是严格证书，不清除8192、不激活策略。

## 未知支持为何没有落在池中

`production-observation.js`遇到新callback、enemy.bullet为空、没有追踪到的敌弹时，直接保留“无弹/未观察弹”的未知关系。这一标记本身没有位置、数量或deadline的显式集合。

`native-base-policy-engine.js:updatePossibleProjectiles`另行构造更具体的软轨迹：上帧可开火、敌方位置方向没有观察变化、没有排他行动证据等条件成立，才从上次枪口生成possible弹，并向当前帧推进。轨迹还会因边界、障碍或可见存活反证而消失。

因此7个根中的空池只说明当前启发式构造器没有活跃轨迹，不说明已经完整枚举并排除全局未知弹丸。池的complete不是InformationState所有世界的覆盖证书。不能把二者混用。

## 实验域

在固定7局目标帧、模拟器step前克隆真实状态，加入一颗敌方弹丸：

- 地图每个非墙/非土、非当前活坦克重叠格；
- 四个朝向；
- 只有加入后整个我方snapshot JSON与原snapshot完全一致，才保留该世界；
- 我方FIRE，敌方NONE/GO/LEFT/RIGHT/FIRE/BOMB/STUN，各自支持的stun随机分支；
- 敌弹已存在导致敌方FIRE不可用的情况由模拟器自行处理，不人为保留不合法的新子弹；
- 一帧结束后按双方crash与星数统计分析胜负，不计runtime。

这是一组当前观察一致的保守位置超集，没有要求每个位置能从历史行动到达；无需把这些世界称为高概率或真实发生。克隆星生成被禁用，仅检查当前单帧终局，不比较未来星序列。

## 支持的机制与限制

固定模拟器先处理行动，再推进弹丸，在弹丸循环之后统一结算死亡。新增的敌弹可以杀死我方，但不一定阻止我方已发出的子弹击毁对手。因此在可靠击毁对手且星数领先时，“自身可能中弹”并不自动意味着终局可能输。

这是需要正式论证的机制，不是可以直接推广的普遍规则。本轮尚未覆盖：

- 多个未知弹丸共同作用，及所有平台允许的数量上限；
- 坦克重叠格等被排除状态的严格不可达性；
- 平台与本地模拟器的弹丸推进/结算顺序差异；
- 其他技能和技能组合、全部事件相位、隐藏炸弹或地形不确定性；
- 生产完整历史支持的一致性证明。

当前敌方stun不能产生overload双弹，但不能仅凭这一点把全局未知弹丸数量任意限定为1。391项旧UT也不是这项新单调性命题的证明。

## 正反fixture

新增独立模拟器fixture：在我方身后加入下一步命中我方的不可见敌弹，并确认snapshot不变。

- 我方领先且开火可击毁对手：同归于尽胜。
- 我方落后：同归于尽负。
- 敌方有盾挡住我方射击：我方单方死亡负。

因此不能做“有星领先就清除弹丸风险”或“开火必然优于躲避”的补丁。必须有对手确实被击毁的完整响应证据，且规则相位支持可靠。

## 下一步

优先定义可复用的终局命题依赖合同：敌方必被击毁、星差结算有利、未知量只可能增加我方死亡而不取消敌方死亡。先对增加弹丸的影响做相位/多实体组合校验及反例；只有独立证据支持，才可豁免该命题不依赖的信息gap，而不是修改全局informationComplete。

冷却技能的未完成响应仍单独处理；本轮没有借模拟器的空操作语义修改FastKernel。
