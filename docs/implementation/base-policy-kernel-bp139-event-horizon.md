# BP139：严格事件horizon无法判向，敌方拒绝暴露必须进入价值而不是证明

BP139没有改变production。它把BP138的固定depth叶改成真正的攻击事件搜索：根动作分别保持
incumbent和candidate，后续使用一个零分配的确定性重规划攻击策略；敌方动作、chance与三个移动规则
世界全部展开。搜索在安全威胁FIRE、严格击毁FIRE、terminal、Hard失败、支持丢失或严格cap处停止。

由于后续我方策略是完整动作域的子集，合同只允许正向证明：`PROVEN`仍是全游戏中存在一条策略的严格
witness；固定策略被反驳或只到cap时一律转换为`UNKNOWN`，不能伪称全动作域`DISPROVEN`。

## 规模修复

第一版完整`7×7` AND/OR depth-4在单场景48/48次搜索都撞到4096节点。仅把FIRE排到前面和加入TT
没有效果。随后先将我方深层域压成最多三个正向代表并降到depth-3，完整率提高到36/48，但仍无证书。

最终版本把后续我方域收敛为一个确定性重规划动作：有清晰射线时转向或FIRE，否则沿主轴推进，前方
阻塞时切副轴。这样最大我方分支为1，可以恢复depth-4。单场景总节点从110,668降到43,149，完整率
从36/48升到42/48；fixed16因此可以在52.8秒内完成。

## fixed16结果

35个方向差异根产生420次`side × goal × movement-world`搜索：

- 390次完整、30次预算不完整；
- 30/35根全维完整，5根至少一个维度不完整；
- 总节点266,310，单搜索最大4096；
- root restore失败0，热路径分配0，整局行为变化0；
- baseline严格事件证书0，candidate严格事件证书0；
- 35根全部是双方均无证书，其中包括2个历史改善和2个历史退化。

372个在固定策略域内得到的负结果都被正确降级为`UNKNOWN`。没有为了获得方向性而把不完整证据升级
成失败，也没有让BP139取得动作所有权。

## 结论

问题不再是horizon太短。严格`∀ EnemyAction`下，敌方可以选择不进入射线、破坏接触或迫使攻击策略
延后；“无法保证所有敌方响应最终都出现安全FIRE”并不等于攻击动作没有价值。敌方为了拒绝暴露而让出
的位置、星路径、接触质量、资源或terminal机会，才是Minimax应该比较的收益。

因此停止继续加深保证开火证明。BP139保留为正向strict certificate诊断，不做owner或veto。BP140应
建立有限时域字典序payoff/regret interval：每个敌方响应仍保留为独立列，但即使没有FIRE，也结算其
terminal/nonloss、位置、星、接触、资源和反击代价；不能重新加入通用ATTACK加分，也不能把历史结果
泄漏到运行时。
