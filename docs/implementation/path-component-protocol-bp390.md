# BP390：第三批十轮路径评分实验预注册

继承高效调优协议 V1。固定 BP386 的 1243 场景 / 2486 换位对局、生产树、V1 确定性时钟、炸弹 phase 适配器、128 节点预算和宿主。全部为实例内诊断包装，生产默认不变，不调用官方接口，不提交推送，不开子 agent。

BP389 的 R15/R16 表明整项路径评分缩小有收益，但该评分混合正奖励和负惩罚。本批对生产基线分别做十个单因素消融，不组合到 R15 上，不把已知历史场景当新盲测。

开发仍为 BP388 的 64 个地图 / 128 局；验证按 sha256(bp390-validation-v1:id) 排序，选 128 个不同地图 / 256 局，排除开发地图及 BP388、BP389 的所有验证地图。结果出炉后不换样本或阈值。全量仍为固定 2486 局。

| 轮次 | 唯一变量 |
|---|---|
| R21 | 仅正 transition 评分减半，全部负值保持 |
| R22 | 仅正 transition 评分归零，全部负值保持 |
| R23 | 仅 FIRE 的有符号 transition 评分减半 |
| R24 | 仅 FIRE 的有符号 transition 评分归零 |
| R25 | 仅 GO 边缘评分归零 |
| R26 | 仅 THROW_BOMB 的正评分归零，保留所有负值（包括逃脱不足惩罚） |
| R27 | 仅完整转向惩罚减半 |
| R28 | 仅移除反向转向的 110 分附加惩罚 |
| R29 | 仅移除连续转向的 60/180/360 附加惩罚，保留线性成本和反向成本 |
| R30 | 仅 CAST_STUN 的 20 分成本归零 |

R21–R24 同时覆盖 scoreTransition / scoreAppliedTransition；后者在当前特化实现为 0。其他子项只改对应 scoreTransition，避免混淆两套参数。整数向零截断，终局、叶值、Hard、Risk、intent 和动作域均不改变。

准备阶段：开发 128 局 noop 与 BP386 逐动作/终局/计数等价；另以统一新包装的 reference-half 重放开发 128 局，与 BP389 R15 已有记录等价（含节点、预算叶），验证新计数入口。两组预检不计入 R21–R30，不作为新策略收益。

晋级门继承：开发净局分至少 +2；验证和全量净局分 >0；单方死亡负局与换位双负不增加；节点不超过同集基线 2 倍；对局 error / timeout / restore 为 0。无行为收益不晋级。通过全量只取得诊断候选资格，生产采用另需移植与等价验证；BP389 R15 仍为已有独立参考。

执行器逐阶段、逐已完成对局保存带校验和的检查点，复用前验证 job、源码身份、场景指纹和行校验和。尾部不完整记录只在明确缺少换行时截去并记录；任何完整行校验失败立即停止。每次进程最多推进一个阶段，避免单一长进程中断。完成文件不可覆盖；所有有效对局均逐局归档，开发/验证已跑过的同一变体对局在全量阶段复用，另记引用与新增执行分母。不会把复用行算作再次执行。
