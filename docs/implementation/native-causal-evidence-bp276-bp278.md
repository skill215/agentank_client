# BP276–BP278：当前帧搜索证据校正

## 范围

本轮只修复开发侧诊断，不改 production 的搜索、Risk、战略、预算或物理规则；不执行平台操作。结果保存在 `artifacts/native-causal-audit/`，避免依赖易失的 `/tmp`。

## 已确认的问题

NativeBasePolicy 在非接触或资源动作拥有当前帧时可能不调用搜索。诊断以前仍读取复用数组中的 membership、backedValue、节点数等，把上一帧数据错误归属于当前帧。即使当前帧调用搜索，非合格行的 backedValue 也不一定写入。

现在通过 prepare 调用记录当前帧证据；未搜索帧的相关字段为空、工作量为零，未赋值行不再把 null 当数值0。lastAction 保存输入前动作，另记 emittedAction。已有历史报告的相关归因不应继续作为修改叶评估器的依据。

## 实测

- BP276：固定16场景，换位32局，20胜9负3平，分析得分67.1875%，星差+4，单方击毁胜14、负5。
- 捕获86个根：49个当前帧调用搜索、37个未调用；未搜索根残留搜索证据为0。
- BP277：按阶段确定性抽取18个根，评估91个动作标签（包含原动作基线，不等于91场独立实验）。9个根当帧搜索，9个未搜索。
- 6个根有更好的终局质量；其中仅3个负→胜，另外3个保持获胜。3个负→胜全部发生在未搜索根：NAVIGATION 1个、INLINE_STABILITY 2个。
- 改善根中仅1对具有可比较的当前搜索值，该对存在值排序与实际续局结果相反；这不足以证明叶函数或Minimax算法错误。
- 候选动作前缀不匹配0、强制动作未执行0。现有反事实工具只校验候选方动作前缀，不是完整双方物理状态等价证书。
- BP278关闭影子诊断：32局、2,708帧与BP276双方动作编码流、星/击毁计数、帧数及分析终局完全一致。不是仅比较总胜率。
- 诊断与上传资格相关UT：9/9通过。

## 解释边界

这些是有选择的诊断根，不是独立胜率样本；反事实以当前V2续局，不能用未来已知结果当在线证书。V1影子阶段名称只是分类标签，不代表V2运行了同名组件。搜索prepare被调用也不代表支持完整、达到目标深度或产生严格证明。

本轮支持优先检查未搜索阶段选择；不支持宣称“Minimax整体有害”或“叶评估已确认错误”。旧BP275的部分归因因陈旧数组问题失去依据，且其原始临时产物当前不可用，不能当成已重新验证证据。

## 下一步

1. 先加强反事实身份：双方前缀、动作参数及完整相关源码指纹；当前六文件closure不是整个引擎依赖闭包。
2. 将未搜索帧分成正常非接触、资源动作拥有、预算/运行模式等真实原因，避免把所有depth=0误叫fallback。
3. 在Discovery扩大同一诊断，分别统计动作候选缺失、风险排除、仲裁选错、搜索值分歧；优先处理有真实负→胜证据的所有权问题。
4. 不根据单点续局oracle直接调分、提高深度或复制V1动作；候选修改仍需整局因果对照。
