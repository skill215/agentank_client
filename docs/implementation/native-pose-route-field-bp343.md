# BP343：包含朝向的静态路线进度模块

## 实现范围

新增诊断模块`PoseRouteField`，对每个“格子×四个朝向”保存到目标的最少基本动作数。一次反向BFS覆盖全部候选位置/朝向；每个GO或转向只需读取两个距离，进度为动作前距离减动作后距离。

模型是静态可通行地图、单格GO、90度左右转各耗一个动作。目标格任意朝向都算到达。墙和土堆不可通行，草与空地可通行。它不模拟眩晕反向、poison速度、boost、teleport、敌方占位、子弹、炸弹或未来地图破坏，因此不是平台完整到达时间，也不是Hard/安全证书。

未连接生产评分或动作仲裁，没有使用本模块绕过Hard/Risk。仅分层128与几何入口的生产状态均不变。

## 进度语义

- 必要绕障碍GO即使增加Manhattan距离，只要减少到达动作数就输出正进度。
- 转向若为下一步移动做正确准备，同样可以输出正进度；反向转错为负。
- 完整原地转一圈的累计进度为0，不能重复获得收益。
- 不可达或无效目标返回UNKNOWN进度（null），不当成0距离、正收益或死亡证明。
- 该势函数只表示目标推进；取得正进度不代表应该最终执行。安全门与攻击策略仍需独立判断。

## 缓存与性能结构

构造时分配distance、queue、terrain三个TypedArray，热方法不创建对象或数组；同一工作区供全部动作读取，不做逐动作BFS。

缓存身份包括地图宽高、目标以及完整地形内容。命中仍逐格比较地形，不只依赖可能被重用的版本号/哈希；目标、障碍、尺寸变化或显式reset都会重建。相同几何地图可以复用，实体与技能不在此静态模型内。

20×20配置固定内存6800字节，最多1600个pose。当前这是独立实验工作区，不宣称已满足production的TypedArray总预算；正式整合需明确复用/替换现有路径数组后再验收，不能悄悄叠加第二套长期世界状态。

## 正确性验证

独立正向BFS oracle枚举所有2×3障碍地图、全部目标、全部起始位置与朝向，9216个比较零差异。额外UT覆盖必要绕行、正确/错误转向、整圈零净进度、不可达、目标已到达、地形变动、目标变动、尺寸变动、reset和容量溢出。

全量Minimax UT374/374通过。这里尚未测试动态危险最短路的实际动作选择，因为模块没有接动作所有者；不能声称已经通过Hard集成或整局胜率验收。

## 微基准

固定Node v24.16.0、20×20合成障碍地图，500次预热/模式，5批各500次，交错模式顺序。每次包括prepare及4次pose读取，结果checksum一致。

| 模式 | 五批P95范围 |
| --- | ---: |
| 强制重建距离场 | 6.974–7.235微秒 |
| 缓存命中（含地形逐格比较） | 0.321–0.331微秒 |

仅是函数级本地成本；亚微秒数字包含计时噪声，不外推完整callback、实际地图分布或官方3000ms。没有运行GC分配分析器，零热对象仅为实现检查结论。
