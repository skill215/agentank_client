# BP396 R81–R90：按当帧状态恢复路径评分

遵循 efficient-tuning-protocol.md。生产默认、Hard、Risk、节点预算、双方 stun、128 帧、bomb-phase 校准器与 V1 确定性时钟不变。不改旧源码／产物，不使用子 agent，不提交发布。

## 假设与单一变量

BP395 中单步恢复首次分歧动作改善了部分死亡，同时损坏非退化对照。首次分歧集中在转向，并出现刚释放 stun 的根。测试以下五个有限条件，每个分别施加于 R15（路径分数减半）和 R29（仅去掉连续转向附加罚分），共十个独立候选：

| 轮次 | 条件 | 候选 |
|---|---|---|
| R81 / R82 | 上一个发出动作为 CAST_STUN | R15 / R29 |
| R83 / R84 | 当前自身 stunUntil 非 NONE 且 > 当前帧 | R15 / R29 |
| R85 / R86 | 已观察到的连续转向次数 >= 1 | R15 / R29 |
| R87 / R88 | 已观察到的连续转向次数 >= 2 | R15 / R29 |
| R89 / R90 | 当前自身星数 < 敌方星数 | R15 / R29 |

条件只在搜索 prepare 入口读取真实根状态并冻结到本次搜索结束；不可按假想后继状态重算。命中时，本次搜索所有 transition / applied-transition 使用生产原始路径评分，否则使用原候选评分。每次 prepare 重置开关。后续动作继续按相同条件策略决定。不读取地图 ID、种子、终局、最佳动作标签或历史 baseline 动作。原评分恢复不是把先前模拟出的 baseline 动作直接插入。

## 冻结样本与门槛

开发集64张实际地形不同的地图：先包含 BP395 所有重复死亡父地图，再按 sha256(bp396-development-v1:matchUrlId) 补足。验证集128张地图按 sha256(bp396-validation-v1:matchUrlId) 排序，排除开发集及 BP394 全部192张证据地图；按实际地形哈希隔离。全部地图此前参加过历史总体分析，因此不是全新盲测。原始历史 seed，不改变 fingerprint。

十轮定义、样本、runner、条件实现、协议和测试哈希在实验前冻结。先重放开发集的生产基线、R15、R29（各128局，共384局），与 BP386 / BP392 已归档原始结果逐动作、参数、分析终局和搜索量等价，再执行候选。

每轮开发128局，同时相对生产和相应未加条件的父候选净局分 >= 2，单方死亡负局和换位双负均不增加，搜索节点比 <= 2；至少一个评分值相对父候选改变。失败立即结束该轮，不观察验证结果调整规则。

通过开发后才运行地图隔离验证256局，同样同时相对生产和父候选净局分 > 0，死亡、双负不增加，节点比 <= 2。再通过才运行原始全量2486局，沿用相同正收益和非退化门槛；开发及验证逐局可按完全相同 job 复用。通过全量只标记 QUALIFIED_DIAGNOSTIC_PENDING_PORTABILITY_AND_MULTISEED，后续仍需源码移植等价与多种子复核，本批不自动采用生产。

## 审计与成本

记录 prepare 次数、条件命中根数、评分调用及相对生产／父候选变化次数。分层结果含双方胜负、单死、双负、节点、动作语义变化和正负局分。双方 error/timeout、rootRestoreFailures、hotAllocations 必须为零。每 stage 一个进程、4 个本地对局 worker，检查点哈希／身份校验后恢复，历史结果只作对照不伪称新执行。运行错误不计完成轮次。每轮拒绝也算完成，不事后改变条件或门槛。

复现：Node v24.16.0 循环调用 conditional-path-campaign.js <新目录>，每次推进一个 stage，直到 rounds.json；随后 conditional-path-report.js <目录> 独立复核。
