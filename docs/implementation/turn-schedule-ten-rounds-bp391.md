## 高效执行与等价性

- 开发 64 个地图和验证 128 个地图全部刷新，均排除 BP388 开发及 BP388/BP389/BP390 验证地图；彼此及历史划分交集均为 0。
- noop 128 局逐动作、终局、计数与 BP386 一致；reference-half 128 局与 BP389 R15 一致；reference-r29 128 局与 BP390 R29 一致，两组参考搜索节点及预算叶也一致。三组预检不算候选轮次，不计新策略收益。
- 每次 runner 进程最多推进一个阶段；每局完成同步追加带 SHA-256 的检查点，重启先验证源码、job、场景和完整行。只有未换行的尾部残片允许截断并记账，完整行校验失败立即停止。
- 全量复用本轮开发/验证的 384 行，逐行验证完全一致；复用次数单独记账。阶段压缩结果和元数据原子写入，完整产物不可覆盖。
- 完整回归 **475/475** 通过；归档对局 error/timeout/restore 均为 0。生产树 `285f9863227d6af3638bed74e008f0260fd25440034d95eec5e3f8cac44d9120`。

## 下一步

本批最高局分的过门候选为 R33，相对 R15 的净局分为 -38。优先复查其按地图去重的正反例与安全退化样本，再决定是否优先于 R15 做独立移植；不因本批排名直接合并参数或替换生产。

本批没有取得高于 R15 或 R29 的全量局分，继续密集扫描相邻系数的优先级降低。下一步建议优先做 R15 的独立移植与等价验证，以 R29 作为较窄改动的对照；R33 保留为成本略低的简化备选，先检查新场景泛化。配对区间并未证明 R15 显著优于所有新候选，不能把点估计排序当作确定优劣。

各轮对照均为同一 BP386：档位、历史方向、搜索层数和星数条件的消融可缩小原因范围，但不能据此推断所有子项的交互收益。进一步组合必须重新预注册并用独立开发隔离集确认。
