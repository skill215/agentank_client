# BP331：同根敌方响应顺序置换

## 结果

**确认当前预算调度下存在动作级顺序敏感性。** 两条既有轨迹，在frame集合15/16/21/22/23上实际进入owner的8个根（包含BP330的6个目标根及GPI21/23），分别进行原顺序、倒序、循环移位重算。

16个置换对比：15个根评分向量变化，6次当前默认owner提案变化（涉及4根），3次WORST_INTENT提案变化（涉及2根）。唯一估值不变项是CM23的循环移位：过滤不参与搜索的列后，实际访问顺序仍为LEFT/RIGHT，相当于重复对照。

| 根 | 原顺序默认提案 | 倒序默认提案 | 移位默认提案 |
| --- | --- | --- | --- |
| CM21 | GO | RIGHT | GO |
| CM22 | RIGHT | GO | GO |
| CM23 | RIGHT | STUN | RIGHT |
| GPI15 | FIRE | GO | GO |

GPI22的WORST_INTENT则从STUN变为RIGHT（倒序、移位均如此）。这不是实际执行变化，而是同根诊断提案。

## 控制条件

- 只置换根敌方列访问顺序；候选集合、概率、递归内部访问顺序、预算配置、深度及评分函数均不变。
- 每次从相同搜索/内核/Hard/估值/路径/状态快照出发，使用独立Hazard实例；重算后逐项校验物理数组恢复。
- 原顺序隔离重算与正常prepare的cell矩阵和根分数完全一致，排除单纯冷缓存产生本轮差异。
- 每种变体均校验双方动作域不变；intent bonus复用原始root，不重新拟合。
- 实际行动仍执行BP326规则，完整双方动作流、参数、结果及计数与冻结轨迹一致；两局只是重建，不是新候选ACTIVE。

真实节点数不完全相同，例如CM22原顺序198、倒序189、移位205。这里控制的是预算配置，不是精确工作量；不同分支展开量及预算尾部工作会改变实际成本，不能据本轮声称性能等价。

## 解释边界

有限预算搜索一般可能对顺序敏感；“不完全不变”本身不自动是实现bug。但结合BP330的大量单节点预算格，以及此处当前默认动作翻转，说明该调度是值得优先修复的质量风险，不能只把低胜率归因于Risk或战略意图。

本轮未改变递归备份，也未测试新调度胜率。不能声称反转列顺序更好，更不能把倒序作为补丁发布。无统计显著性结论。

## 下一步：预算调度POC，而非新排序

固定当前默认混合评分与intent，建立诊断版分层矩阵调度：

1. 所有保留动作×敌方响应先完成共同浅层结果。
2. 深化写入工作矩阵；只有完整层完成才替换可用矩阵。
3. 中断时保留最后完整层，不把同一矩阵不同深度估计伪装成完整结果。
4. 完成深度不等于严格Proof，response residual与物理不完整继续单独标记。
5. 预算、节点计数和尾部开销必须实测；不能靠抬预算获得假改进。

先做小树oracle、完成层/中断UT、缓存开关一致和本轮同根顺序置换，再决定是否进入固定16场景ACTIVE。暂不修改生产默认、Risk、intent或战略层；不立即大规模重跑对战。
